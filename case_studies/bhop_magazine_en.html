The Problem

Grant consulting is a time trap

A typical grant consultant spends 40-60 hours per client engagement: profiling the organization, scouring databases for matching calls, checking eligibility on each one, drafting the proposal, building the budget, pricing the engagement. Most of that work happens before anyone knows if the grant is even winnable.

For micro-nonprofits like B-HOP — annual budget under €12k, no grant track record, no dedicated staff — the math is brutal. The consultant's fee often approaches the grant amount itself. One wrong call on feasibility means dozens of wasted hours.

The core question

Can you build a system that does the analysis work — profiling, matching, feasibility, drafting, pricing — so the consultant only spends time on what's actually viable?

The Solution

A 7-prompt chain, end to end

Each prompt takes the output of the previous one as input. The chain runs sequentially in a single conversation. No custom code, no API — just structured prompts with strict input/output contracts.

The Gatekeeper Effect

The chain didn't just find matches. It caught 3 grants that looked promising on paper but would have wasted the consultant's time. All three EU grants (CERV-VALUES, CERV-REM, Creative Europe) failed on the same structural issue:

What I Learned

1. Criteria first, writing second

The proposal draft starts from the funder's evaluation grid, not from a blank page. Every section maps to a criterion, weighted by importance. This is obvious in theory — almost nobody does it in practice.

2. The chain is a gatekeeper, not an accelerator

The biggest value isn't speed. It's stopping work on non-viable grants before the consultant invests real hours. 3 out of 7 grants blocked = ~30 hours not wasted.

3. Incomplete data is a feature

When the client profile is 59% complete, the chain says "SUSPENDED" — not "probably fine." This is the correct behavior. A system that guesses on missing data is worse than no system at all.

4. Pricing kills bad deals early

P4 showed that success-fee pricing has negative expected value at 30% win probability. Without that math, the consultant might have taken the job on success fee and lost money. The flat fee model — the only viable one — was identified automatically.
